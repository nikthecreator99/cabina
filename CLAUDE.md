# CABINA — заметки для работы над проектом

CABINA — личное PWA-приложение для машинистов и помощников машиниста: учёт поездок, рабочего времени,
ночных и праздничных часов, нормы по производственному календарю, отвлечений (больничный, отпуск,
медкомиссия), отдыха, заметок о локомотивах и рабочих документов. Не является официальной системой ОАО «РЖД»
и не должно так позиционироваться (название и логотип РЖД — товарные знаки).

- Живой адрес: https://nikthecreator99.github.io/cabina/ (GitHub Pages, ветка `main`, корень репозитория).
- Всё, что попадает в `main`, сразу публикуется. Сборки нет: сайт — это файлы репозитория как есть.
- Владелец — Никита, не разработчик. Общение по-русски, простым языком, без жаргона.

## Устройство

Чистый HTML/CSS/JS (ES-модули), без библиотек и сборки. Данные — только в IndexedDB на устройстве
пользователя, на сервер ничего не уходит.

| Файл | Что внутри |
|---|---|
| `index.html` | оболочка, нижнее меню, ранняя установка темы |
| `js/app.js` | экраны (Главное, Маршруты, Дополнительно, Настройки), навигация, свайпы, обновление версии, `VERSION` |
| `js/forms.js` | формы поездки, отвлечения, маршрута, заметки; расчёт домашнего отдыха и поиск поездки «туда и обратно» |
| `js/calc.js` | все расчёты: рабочее время, ночные (22:00–06:00), праздничные, итоги месяца, отдых, форматирование |
| `js/calendar.js` | производственный календарь РФ: официальные данные 2026–2027 + прогноз по ТК РФ для остальных лет |
| `js/store.js` | состояние в памяти (`S`) и сохранение; нормализация локомотивов |
| `js/db.js` | обёртка IndexedDB (база `cabina`, версия 1), запасной режим в памяти |
| `js/backup.js` | резервная копия в JSON (`app: 'CABINA'`, `format: 1`) и восстановление |
| `js/docs.js` | рабочие документы: папки, файлы (blob в IndexedDB) |
| `js/tour.js`, `js/tours.js` | подсказки первого запуска: механизм и тексты |
| `js/sun.js` | восход/закат по городу часового пояса — для картинки неба на главном экране |
| `js/ui.js` | иконки, окна (sheet/dialog), тосты, даты по-русски |
| `sw.js` | service worker: офлайн-кэш `SHELL`, `VERSION` |
| `data/changelog.json` | список «Что нового» (берётся всегда с сервера) |
| `data/calendar.json` | обновление календаря без выпуска версии |

### Важные правила в коде

- **Время хранится «настенным»**: строка `'YYYY-MM-DDTHH:mm'` в часовом поясе пользователя. В миллисекунды
  переводится как UTC-наивное (`parseLocal`), поэтому все `Date` в расчётах читаются через `getUTC*`.
  Не использовать локальные методы `Date` для дат поездок.
- «Сейчас» — `nowLocal()` из `store.js` (учитывает часовой пояс из настроек).
- Хранилища IndexedDB: `trips`, `absences`, `routes`, `notes`, `files`, `blobs`, `meta`. Если меняется
  схема — поднять `DB_VERSION` в `db.js` с миграцией и не терять данные пользователей. Формат резервной
  копии (`format`) — тоже поднимать с обратной совместимостью при импорте.
- Поля поездки: `id, routeId, routeLabel, start, end, passenger[{id,start,end}], locoType, locoNumber,
  restType ('turnaround'|'home'), homeRest {ids}, createdAt, updatedAt`. У всех записей уникальный `id`
  (основа будущей синхронизации).
- Текст пользователя всегда выводить через `esc()`.

### Формулы (согласованы с владельцем)

- Рабочее время = объединение интервалов поездки и следования пассажиром (без двойного счёта).
- Поездка через полночь месяца делится по месяцам.
- Ночные — часы с 22:00 до 06:00. Праздничные — только часы внутри официальных нерабочих праздничных дней
  (не выходных по переносу).
- Норма месяца = часы по календарю (8 ч, предпраздничный 7 ч) − часы отвлечений. Отвлечение по умолчанию
  вычитает рабочие часы своих дней по календарю, можно вписать часы вручную по месяцам.
- Отдых в пункте оборота = max(рабочее время / 2, минимальный отдых из настроек; по умолчанию 4 ч).
- Полный (домашний) отдых = (сумма рабочего времени выбранных поездок) × 2,6 − (сумма промежутков между
  соседними поездками). «С выходным» = +24 ч. Можно по одной поездке.
- «Туда и обратно» (`suggestChain`): от текущей поездки назад по предыдущим, пока у них «Отдых в пункте
  оборота», перерыв ≤ 48 ч и станции стыкуются. Дом отдыха — станция прибытия поездки с отдыхом в пункте оборота.

## Тесты

```bash
npm install            # один раз: ставит Playwright
npm test               # расчёты, календарь, согласованность версии (быстро, без браузера)
npm run test:e2e       # сценарии в браузере на экране телефона 390×844
npm run test:all       # всё вместе
npm run serve          # открыть приложение локально: http://localhost:8080
```

- `tests/unit/` — `node:test`, импортируют модули из `js/` напрямую.
- `tests/e2e/` — Playwright без тест-раннера Playwright (тоже `node:test`). «Сейчас» зафиксировано на
  20.10.2026 12:00 МСК (`helpers.js`), подсказки выключены через `localStorage['cabina-tours-off']`,
  данные можно записать напрямую через `seed()`.
- Если Chromium для Playwright не установлен: `npx playwright install chromium`, или укажите свой путь
  в `CHROMIUM_PATH`.
- `tests/unit/release.test.js` проверяет, что версия в `js/app.js`, `sw.js` и первой записи
  `data/changelog.json` совпадает, и что каждый файл из `js/` есть в `SHELL`.

Новая функция — новые тесты. Перед отправкой результата владельцу: все тесты зелёные, ошибок в консоли нет,
каждая затронутая кнопка проверена в браузере (это его прямое требование).

## Выпуск версии

1. Поднять `VERSION` в `js/app.js` и `sw.js` (`cabina-vX.Y.Z`) — одинаково.
2. Добавить запись **в начало** `data/changelog.json`: версия, дата, пункты простым языком для пользователя
   (их видно в окне «Новая версия» перед обновлением и в «Настройки → Что нового»).
3. Новый файл в `js/`, `css/`, `icons/`, `fonts/` — добавить в `SHELL` в `sw.js`.
4. Изменился смысл подсказки — сменить id тура в `tours.js` (`'routes2'` → `'routes3'`), чтобы она
   показалась пользователям снова.
5. `npm run test:all`, коммит в `main`, push. Через 1–2 минуты проверить живой адрес.
6. У пользователей появится окно «Новая версия» с кнопкой «Обновить»; данные при обновлении сохраняются.

## Договорённости по интерфейсу

- Подсказки первого запуска: только кнопки «Дальше» / «Понятно» (без «Пропустить»), стрелки дугой,
  порядок шагов всегда сверху вниз и слева направо.
- Удаление поездок и маршрутов — свайпом влево, затем вопрос «Вы действительно хотите удалить…?» с «Да / Нет».
- Оформление в духе иконки (закат, лес, поезд с фарами); небо на главном экране меняется по восходу и закату.
  Тема сейчас по умолчанию «Как в системе» (в 2.0 планируется убрать этот вариант и сделать тёмную по умолчанию).
- Не показывать пустую статистику и нулевые строки.
