# Сервер CABINA

Сервер нужен только для аккаунтов. Без аккаунта CABINA работает как раньше: все записи остаются в телефоне.
Сервер — Supabase на VPS Beget в российском дата-центре (152-ФЗ, ст. 18 ч. 5).

**В этой папке нет и не должно быть секретов.** Репозиторий публичный. Ключи `service_role`, `JWT_SECRET`,
пароль базы и почты создаются на самом сервере и хранятся только там и в менеджере паролей владельца.
Почта администратора тоже не пишется в репозиторий.

## Что хранится на сервере (шаг 1)

| Таблица | Что внутри | Кто видит |
|---|---|---|
| `auth.users` | почта, хеш пароля (встроенный вход Supabase) | сам человек через `export_my_data()` |
| `public.profiles` | роль, дата регистрации, дата последнего захода (без времени), платформа, версия | только сам человек |
| `public.consents` | какой документ и в какой редакции принят, когда | только сам человек |
| `private.invites` | хеш кода-приглашения, срок, кем использован | никто через API |
| `private.stats_daily` | числа за день: регистрации, подтверждения почты, удаления | администратор через `admin_stats()` |

Поездки, заработок, отвлечения и профиль из телефона на сервер не отправляются.

## Функции для приложения

- регистрация — обычный `supabase.auth.signUp` с `options.data = { consent: 'privacy-1', invite, platform, version }`.
  Без согласия текущей редакции (и, пока включён закрытый режим, без живого приглашения) аккаунт не создаётся;
  после регистрации эти данные из аккаунта стираются;
- `touch(platform, version)` — отметка «заходил сегодня»;
- `export_my_data()` — всё, что сервер знает о человеке;
- `delete_my_account()` — удаление аккаунта и всего, что с ним связано (это же отзыв согласия);
- `admin_stats()`, `admin_create_invite()` — только для роли `admin`.

Писать в таблицы напрямую из приложения нельзя: только эти функции.

## Автотесты («стенд»)

```bash
npm run test:server
```

Тесты поднимают временную базу PostgreSQL (нужны программы PostgreSQL 15+; путь — в `PG_BIN`, если они не в
`/usr/lib/postgresql/*/bin`), ставят упрощённую копию Supabase (`tests/supabase-stub.sql`) и все миграции.
Проверяется: чужой не видит и не меняет мои данные; без входа не видно ничего; у каждой таблицы есть RLS;
удаление аккаунта стирает всё; статистика — только числа и только администратору; IP в журналах — не дольше 30 дней.
Новая таблица без RLS или без `on delete cascade` к `auth.users` роняет тесты.

## Правила изменения базы

- Каждое изменение — новый файл `migrations/NNNN_что.sql`. Старые файлы не правим после выкладки на сервер.
- Новая таблица: RLS, правило «своё», `on delete cascade` к `auth.users`, тест «чужой не видит».
- Новая функция в `public`: `security definer`, `set search_path = ''`, проверка `auth.uid()`, без доступа для `anon`.
- Перед изменением — чек-лист из раздела 1.4 `CLAUDE.md`.

## Настройка на сервере (кратко; пошаговая инструкция — в отдельном документе для владельца)

1. VPS на Beget в России, Supabase из каталога. Вход по SSH только по ключу, пароль для SSH выключен.
2. Наружу открыт только HTTPS-адрес API. Supabase Studio и порт базы снаружи закрыты (доступ — через SSH-туннель).
3. Настройки входа (GoTrue): подтверждение почты обязательно, пароль от 10 символов, ограничение попыток,
   письма — через почту Beget на нашем домене. Вход через Google, Apple, Telegram и т.п. выключен (149-ФЗ, ст. 8 ч. 10).
4. Телеметрия Supabase и любая внешняя аналитика выключены.
5. Применить миграции по порядку (`psql -f migrations/0001_accounts.sql` через SSH-туннель).
6. Ежедневная очистка журналов: `select cron.schedule('cabina-cleanup', '15 3 * * *', 'select private.cleanup_logs()');`
7. Первый администратор — после своей регистрации, в консоли сервера:
   `update public.profiles set role = 'admin' where id = (select id from auth.users where email = '…');`
8. Резервные копии каждую ночь, зашифрованные, в России, хранение 14 дней; раз в месяц — проверка восстановления.
9. Прогнать на настоящем сервере те же проверки, что в автотестах (особенно удаление из `auth.users` от имени функции).

Закрытый режим выключается только перед открытием регистрации для всех:
`update private.config set value = 'false' where key = 'invite_only';`
